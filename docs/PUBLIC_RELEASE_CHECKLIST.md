## 3. Mandatory Pre-Publication Gates

Before repository visibility is changed from private to public, or any release is published, the maintainer MUST complete the following gates:

### Gate A: Multi-Branch & Git History Privacy Decision Gates
> [!CAUTION]
> **CRITICAL REPOSITORY PRIVACY & PERSISTENCE NOTICE**:
> Current-tree cleanup alone **does NOT** guarantee Git history privacy. Changing repository visibility from private to public on GitHub will expose **every remote ref and every reachable commit object**.
>
> Furthermore, **deleting remote branches or running `git-filter-repo` alone does not prove privacy on GitHub**: GitHub retains cached views, internal reference trees, and commit objects associated with pull requests (e.g. `refs/pull/*`) even after branches are deleted or rewritten on the remote. Deletion and rewriting cannot be undone without a verified backup and must be treated as explicit maintainer decision gates, never automatic or destructive cleanup steps.

- [ ] **Ref & Commit Inventory First**: Perform a read-only audit of all remote branches (`git branch -r`), reachable tags, and historical commit authors/committers to catalogue privacy findings before deciding on any modification.
- [ ] **PR & Issue Metadata Audit**: Review pull request titles, issue descriptions, and historical comments for personal email addresses, paths, or tokens retained in GitHub metadata.
- [ ] **Explicit Maintainer Authorization Required**: No remote branches may be deleted, and no history rewriting tool (such as `git-filter-repo`) may be run without explicit, formal maintainer authorization for that specific action.
- [ ] **Verified Recoverable Backup**: Before executing any authorized history rewrite or branch pruning, create and verify a complete, restorable local repository bundle:
  ```bash
  git bundle create tessera-pre-rewrite-backup.bundle --all
  git bundle verify tessera-pre-rewrite-backup.bundle
  ```
- [ ] **Selected History Sanitization (Gated Decision)**: If and only if authorized by the maintainer, execute targeted rewriting on designated surviving branches, followed by verification that dangling objects and references are accounted for.
- [ ] **Post-Rewrite Ref Verification**: Re-verify repository refs and commit reachability (`git log -p --all`, `git fsck --unreachable`) against the privacy scanner before any visibility change.
